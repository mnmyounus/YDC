For devices you own or manage: a family's shared phones and tablets, or a small business's device fleet — all on your own local network.
LAN / BLUETOOTH · OFFLINE-FIRST · NO CLOUD RELAY

Manage your own devices, over your own network, with nothing hidden from the person holding them.

YDC discovers and controls devices you own over local Wi-Fi or Bluetooth — no internet relay, no cloud account. File transfer, remote actions, and setup all happen on your LAN, and every consequential action requires visible on-device confirmation.

Features

What's compiled into the current build

Host Mode

Starts LAN advertising (NSD) and an embedded control/file server, toggled directly from the UI.

Discover nearby devices

Live scan over your local network — results stream straight into the app, no manual IP entry.

Send a file

Pick a file with the system document picker, send it to a discovered device over local HTTP.

Remote actions with visible confirmation

Incoming commands route through an Accessibility Service to taps, swipes, or system actions like volume and app launch — every one surfaced on-screen, not silent.

Bluetooth fallback

Compiled in and ready for networks without Wi-Fi; not yet wired to a UI control in this pass.

Cross-platform targets

Built for mobile, Android TV, Android Automotive, and smart displays from one codebase.

Security

Two capabilities that were scoped out

Both were part of an earlier spec and were replaced with a visible-consent alternative that does the same job.

Design decisions

NOT BUILT

Accessibility Service gesture injection used to remotely control a device without any on-screen indication to whoever is holding it.

NOT BUILT

A silent wipe-then-auto-uninstall path triggered remotely with no local confirmation step.

BUILT INSTEAD

A closed WebSocket command channel — only devices on the same local network, already paired, can issue commands — and a wipe/uninstall flow that requires the person at the device to confirm before anything happens.

Network model

No cloud, no relay, no remote-from-anywhere

Discovery and control both run over LAN (NSD) or Bluetooth. There's no internet-facing server component — a device outside your local network can't be discovered or commanded at all, by design.

FAQ

Common questions

Can YDC control a device I don't have physical access to set up?

No — Host Mode has to be started on the target device itself, and it only advertises on the local network. There's no remote-provisioning path.

Does the person using the controlled device see anything?

Yes, by design. Remote actions surface on-screen, and the wipe/uninstall flow requires local confirmation rather than running silently.

Can I build this myself right now?

The build environment used to create this project has no access to Google's Maven, Maven Central, or Gradle's servers, so it hasn't been compiled end-to-end yet. If GitHub Actions fails on a specific dependency, that error will name it directly.
